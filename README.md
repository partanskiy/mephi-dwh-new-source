# Добавление нового источника в DWH

Учебный проект по дисциплине "Работа с данными в хранилище".
МИФИ, магистратура "Высшая аналитика данных", Data Engineering, семестр 3.

Маркетплейс товаров ручной работы приобрёл ещё один сайт. Нужно включить
его данные в существующее хранилище и построить ежемесячную инкрементальную
витрину по заказчикам `dwh.customer_report_datamart`.

**Статус:** подготовлены условие и структура репозитория.
SQL-решение и результаты проверки в БД будут добавлены на следующем этапе.

## Объём будущего решения

1. Изучить реальные таблицы и данные схемы `external_source`.
2. Дополнить загрузку из трёх источников данными `craft_products_orders`
   и `customers`, разложив их по измерениям и фактам `dwh`.
3. Создать `dwh.customer_report_datamart` и таблицу учёта загрузок.
4. Реализовать инкрементальное обновление витрины по заказчикам за месяц.
5. Проверить расчёты, повторные загрузки, отсутствие дублей и пропусков.

Все 19 требуемых полей перечислены в условии. В учебном тексте и описании
схемы встречаются разные написания имён таблиц, например
`craft_product_orders` и `craft_products_orders`. Фактические имена и типы
нужно сверить с учебной БД перед реализацией.

## Подключение

По условию используется БД предыдущих модулей: порт `6432`, аутентификация
`Database Native`. Хост, имя базы, пользователь и пароль выдаёт сервис
проверок; конкретные значения хранятся локально.

Для подготовки локальных настроек можно скопировать шаблон:

```bash
cp .env.example .env
```

Заполните `.env` своими параметрами. Это заготовка для последующей работы:
автоматической загрузки `.env` и команды запуска решения пока нет.
Файлы `.env`, `.pgpass`, локальные настройки и выгрузки исключены из Git.
